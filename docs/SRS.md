## 1. Введение

### 1.1 Назначение документа
Данный документ содержит полную спецификацию функциональных и нефункциональных требований к мобильному приложению "StudentCounter" - системе управления учебными задачами и дедлайнами для студентов.

### 1.2 Область применения
Приложение предназначено для студентов высших и средних учебных заведений для организации учебного процесса, отслеживания дедлайнов по различным предметам и своевременного получения уведомлений о приближающихся сроках сдачи работ.

- **Дедлайн** - Крайний срок сдачи учебной работы

## 2. Общее описание

### 2.1 Описание продукта
"StudentCounter" - мобильное приложение для операционных систем iOS и Android, позволяющее студентам эффективно управлять учебными задачами, отслеживать дедлайны и получать своевременные напоминания о предстоящих сроках сдачи работ.

### 2.2 Функции продукта
Основные функции приложения:
- Управление списком учебных предметов
- Создание, редактирование и удаление задач по предметам
- Установка дедлайнов с точностью до минуты
- Настройка множественных уведомлений для каждой задачи
- Push-уведомления со звуковым сопровождением
- Локальное хранение всех данных на устройстве

### 2.3 Характеристики пользователей
**Целевая аудитория:** Студенты ВУЗов и СУЗов

**Характеристики:**
- Возраст: 17-30 лет
- Уровень технической грамотности: средний и выше
- Потребность: организация учебного процесса, контроль дедлайнов
- Платформы: iOS, Android

**Типы пользователей:**
- **Студент** - основной пользователь системы, использует все функции приложения

### 2.4 Ограничения
- Приложение работает только на мобильных устройствах (iOS/Android)
- Требуется разрешение на отправку push-уведомлений
- Данные хранятся локально, не синхронизируются между устройствами
- Отсутствует многопользовательский режим
- Отсутствует облачное хранилище данных

### 2.5 Предположения и зависимости
- Устройство пользователя работает на iOS 13+ или Android 5.0+
- Пользователь предоставил разрешение на отправку уведомлений
- На устройстве достаточно свободного места для хранения данных
- Системные часы устройства настроены корректно

## 3. Функциональные требования

### 3.1 Управление предметами

#### 3.1.1 Создание предмета
**ID:** FR-1.1  
**Приоритет:** Высокий  
**Описание:** Пользователь может создать новый учебный предмет.

**Входные данные:**
- Название предмета (обязательное, строка, 1-100 символов)
- Цвет предмета (обязательное, выбор из палитры)

**Выходные данные:**
- Новый предмет добавлен в список
- Уведомление об успешном создании

**Бизнес-правила:**
- Название предмета должно быть уникальным
- Цвет используется для визуального различения предметов

#### 3.1.2 Просмотр списка предметов
**ID:** FR-1.2  
**Приоритет:** Высокий  
**Описание:** Пользователь может просматривать список всех созданных предметов.

**Выходные данные:**
- Список предметов с отображением:
  - Названия
  - Цвета
  - Количества активных задач

#### 3.1.3 Удаление предмета
**ID:** FR-1.3  
**Приоритет:** Средний  
**Описание:** Пользователь может удалить предмет.

**Входные данные:**
- Идентификатор предмета

**Выходные данные:**
- Предмет удален из системы
- Подтверждение удаления

**Бизнес-правила:**
- При удалении предмета удаляются все связанные задачи
- Требуется подтверждение действия

### 3.2 Управление задачами

#### 3.2.1 Создание задачи
**ID:** FR-2.1  
**Приоритет:** Критический  
**Описание:** Пользователь может создать новую задачу по предмету.

**Входные данные:**
- Название задачи (обязательное, строка, 1-200 символов)
- Предмет (обязательное, выбор из списка или создание нового)
- Дата и время дедлайна (обязательное, дата в будущем)
- Описание (необязательное, строка, до 1000 символов)
- Список временных интервалов для уведомлений (множественный выбор)

**Выходные данные:**
- Новая задача добавлена в список
- Запланированы уведомления
- Уведомление об успешном создании

**Бизнес-правила:**
- Дедлайн не может быть в прошлом
- Можно выбрать несколько временных интервалов уведомлений
- При создании предмета из задачи, предмет также сохраняется

#### 3.2.2 Просмотр списка задач
**ID:** FR-2.2  
**Приоритет:** Критический  
**Описание:** Пользователь может просматривать список всех задач.

**Выходные данные:**
- Список задач с отображением:
  - Названия задачи
  - Названия и цвета предмета
  - Даты и времени дедлайна
  - Статуса выполнения
  - Активных уведомлений

**Бизнес-правила:**
- Задачи сортируются по дате дедлайна (ближайшие сверху)
- Просроченные задачи выделяются красным цветом

#### 3.2.3 Редактирование задачи
**ID:** FR-2.3  
**Приоритет:** Высокий  
**Описание:** Пользователь может редактировать существующую задачу.

**Входные данные:**
- Идентификатор задачи
- Обновленные данные (см. FR-2.1)

**Выходные данные:**
- Задача обновлена
- Перепланированы уведомления
- Уведомление об успешном сохранении

**Бизнес-правила:**
- Применяются те же правила валидации, что и при создании
- Старые уведомления отменяются, создаются новые

#### 3.2.4 Удаление задачи
**ID:** FR-2.4  
**Приоритет:** Средний  
**Описание:** Пользователь может удалить задачу.

**Входные данные:**
- Идентификатор задачи

**Выходные данные:**
- Задача удалена
- Отменены все уведомления
- Подтверждение удаления

#### 3.2.5 Отметка задачи как выполненной
**ID:** FR-2.5  
**Приоритет:** Высокий  
**Описание:** Пользователь может отметить задачу как выполненную.

**Входные данные:**
- Идентификатор задачи
- Статус выполнения (boolean)

**Выходные данные:**
- Статус задачи изменен
- Визуальная индикация выполнения
- При необходимости отменены уведомления

### 3.3 Система уведомлений

#### 3.3.1 Настройка уведомлений
**ID:** FR-3.1  
**Приоритет:** Критический  
**Описание:** Система позволяет настраивать временные интервалы уведомлений.

**Доступные интервалы:**
- 14 дней до дедлайна
- 7 дней до дедлайна
- 5 дней до дедлайна
- 3 дня до дедлайна
- 1 день до дедлайна
- 12 часов до дедлайна
- 6 часов до дедлайна
- 3 часа до дедлайна
- 1 час до дедлайна
- 30 минут до дедлайна
- В момент дедлайна

**Бизнес-правила:**
- Можно выбрать несколько интервалов одновременно
- Уведомления не планируются для прошедших времен

#### 3.3.2 Отправка уведомлений
**ID:** FR-3.2  
**Приоритет:** Критический  
**Описание:** Система отправляет push-уведомления в установленное время.

**Характеристики уведомления:**
- Заголовок: "Напоминание о задаче"
- Текст: название задачи + время до дедлайна
- Звуковое сопровождение
- Вибрация (на Android)

**Бизнес-правила:**
- Уведомления отправляются даже при закрытом приложении
- Требуется предварительное разрешение пользователя

#### 3.3.3 Запрос разрешений
**ID:** FR-3.3  
**Приоритет:** Высокий  
**Описание:** Приложение запрашивает разрешение на отправку уведомлений при первом запуске.

**Выходные данные:**
- Системный диалог запроса разрешений
- Сохранение статуса разрешения

### 3.4 Хранение данных

#### 3.4.1 Локальное хранилище
**ID:** FR-4.1  
**Приоритет:** Критический  
**Описание:** Все данные сохраняются локально на устройстве.

**Сохраняемые данные:**
- Список предметов
- Список задач
- Статусы выполнения
- Настройки уведомлений

**Бизнес-правила:**
- Данные сохраняются автоматически после каждого изменения
- Данные загружаются при запуске приложения

## 4. Нефункциональные требования

### 4.1 Требования к производительности
**ID:** NFR-1  
**Приоритет:** Высокий

- Время запуска приложения: не более 2 секунд
- Время отклика UI на действия пользователя: не более 300 мс
- Поддержка до 1000 задач без снижения производительности
- Плавная анимация интерфейса (60 FPS)

### 4.2 Требования к надежности
**ID:** NFR-2  
**Приоритет:** Критический

- Приложение не должно терять данные при сбое
- Корректная работа при отсутствии интернета (офлайн-режим)
- Точность отправки уведомлений: ±1 минута
- Автоматическое восстановление данных из локального хранилища

### 4.3 Требования к удобству использования
**ID:** NFR-3  
**Приоритет:** Высокий

- Интуитивно понятный интерфейс
- Минимальное количество действий для создания задачи (не более 5 шагов)
- Поддержка альбомной и портретной ориентации
- Поддержка различных размеров экранов (от 4" до планшетов)
- Адаптивный дизайн для iOS и Android

### 4.4 Требования к совместимости
**ID:** NFR-4  
**Приоритет:** Высокий

- **iOS:** версия 13.0 и выше
- **Android:** версия 5.0 (API level 21) и выше
- Поддержка темной и светлой темы системы
- Соответствие Human Interface Guidelines (iOS) и Material Design (Android)

### 4.5 Требования к безопасности
**ID:** NFR-5  
**Приоритет:** Средний

- Данные хранятся локально на устройстве пользователя
- Отсутствие передачи данных третьим лицам
- Защита данных средствами операционной системы (песочница приложения)

### 4.6 Требования к сопровождению
**ID:** NFR-6  
**Приоритет:** Средний

- Модульная архитектура кода
- Документированный код
- Использование TypeScript для типобезопасности
- Соответствие ESLint правилам

### 4.7 Требования к локализации
**ID:** NFR-7  
**Приоритет:** Низкий

- Интерфейс на русском языке
- Формат даты и времени согласно локали устройства
- Возможность добавления других языков в будущем

## 5. Требования к интерфейсу

### 5.1 Интерфейс пользователя

#### 5.1.1 Общие требования к UI
- Минималистичный, лаконичный дизайн
- Цветовая дифференциация предметов
- Четкая визуальная иерархия элементов
- Использование иконок для основных действий
- Модальные окна для создания/редактирования

#### 5.1.2 Экран "Задачи" (главный)
**Компоненты:**
- Список задач с карточками
- Кнопка добавления новой задачи (FAB)
- Фильтрация и сортировка (опционально)

**Информация на карточке задачи:**
- Название задачи
- Название и цвет предмета
- Дата и время дедлайна
- Иконки активных уведомлений
- Чекбокс выполнения
- Кнопки редактирования и удаления

#### 5.1.3 Экран "Предметы"
**Компоненты:**
- Список предметов с карточками
- Кнопка добавления нового предмета (FAB)
- Счетчик активных задач по каждому предмету

**Информация на карточке предмета:**
- Название предмета
- Цветовой индикатор
- Количество задач
- Кнопка удаления

#### 5.1.4 Модальное окно создания/редактирования задачи
**Поля:**
- Текстовое поле: Название задачи
- Выбор предмета (dropdown с возможностью создания нового)
- Выбор даты (календарь)
- Выбор времени (время пикер)
- Текстовое поле: Описание (опционально)
- Множественный выбор уведомлений
- Кнопки: "Сохранить", "Отмена"

**Требования:**
- Календарь и время пикер отображаются inline под кнопкой выбора
- Даты и время должны быть хорошо видимы
- Кнопки крупные, удобные для нажатия

#### 5.1.5 Модальное окно создания предмета
**Поля:**
- Текстовое поле: Название предмета
- Выбор цвета (палитра)
- Чекбокс: "Создать задачу для этого предмета"
- Кнопки: "Сохранить", "Отмена"

### 5.2 Требования к элементам управления
- Минимальный размер кнопок: 44x44 pt (iOS), 48x48 dp (Android)
- Тактильная обратная связь при нажатии
- Визуальные состояния: default, pressed, disabled
- Использование нативных компонентов платформы где возможно

### 5.3 Навигация
- Таб-навигация между основными экранами (Задачи, Предметы)
- Модальные окна для создания/редактирования
- Кнопка "Назад" в заголовке модальных окон
- Плавные анимации переходов

## 6. Системные требования

### 6.1 Архитектура приложения
**Технологический стек:**
- React Native 0.74+
- Expo SDK 51+
- TypeScript 5.3+
- Expo Router для навигации
- AsyncStorage для хранения данных
- Expo Notifications для push-уведомлений

**Архитектурный паттерн:**
- Service Layer (services/) - работа с данными и API
- Business Logic Layer (hooks/) - бизнес-логика и состояние
- Presentation Layer (components/, app/) - UI компоненты
- State Management: Context API + Custom Hooks

### 6.2 Структура проекта
```
app/                    # Expo Router pages
├── (tabs)/            # Tab navigation
│   ├── index.tsx      # Tasks screen
│   └── subjects.tsx   # Subjects screen
├── add-task.tsx       # Add task modal
├── edit-task.tsx      # Edit task modal
└── add-subject.tsx    # Add subject modal

services/              # Data layer
├── storage.service.ts # AsyncStorage operations
└── notification.service.ts # Notifications API

hooks/                 # Business logic
├── useTasks.tsx       # Tasks management
└── useSubjects.tsx    # Subjects management

contexts/              # Global state
├── TasksContext.tsx   # Tasks state provider
└── SubjectsContext.tsx # Subjects state provider

components/            # UI components
├── TaskCard.tsx       # Task display component
├── SubjectCard.tsx    # Subject display component
└── NotificationPicker.tsx # Notification selector

constants/             # Configuration
├── theme.ts           # Colors, typography
└── types.ts           # TypeScript types
```
